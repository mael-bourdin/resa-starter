# Definition of Ready

Un ticket est **prêt** quand l'équipe peut commencer à travailler dessus sans poser de question.

## Critères

- [ ] **Titre clair** : on comprend le problème ou le besoin en une phrase.
- [ ] **Contexte** : pourquoi on le fait, pour qui (exemple concret ou étapes pour reproduire un bug).
- [ ] **Critères d'acceptation** : une liste de cases à cocher, vérifiables par un test ou une démonstration.
- [ ] **Taille raisonnable** : faisable en moins d'une demi-journée. Sinon, on le découpe.
- [ ] **Dépendances connues** : les tickets qui doivent passer avant sont identifiés.
- [ ] **Label** posé (`env`, `git`, `securite`, `ui-metier`, `agile`, `bug`).
- [ ] **Assigné** à un membre de l'équipe.

## Si un critère manque

Le ticket reste dans le backlog. On le complète avant de créer la branche.
